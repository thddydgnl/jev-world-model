# 실험 계획 — 확장 논문

작성 2026-09-23 (계획 단계). KIIS 2026 추계의 2×2 비교를 출발점으로, 사용자 제안 네 가지를 모두 담는다:
여러 step 세계모델, JEV 방식과 일반 LLM(생성형) 세계모델의 비교, JEV 방식을 학습한 LLM으로 얻기,
ALFWorld·ScienceWorld로의 확장. 여기에 KIIS에서 뺀 것(학습 곡선, 일반화, 긴 horizon, 질의 분해)을 더한다.

**시작 조건: KIIS 최종 제출(10/23) 뒤.** 그 전에는 이 문서를 고치기만 하고 실험은 하지 않는다.

---

## 0. 한 문장과 네 질문

> LLM 에이전트의 세계모델에서 타입화된 판단(JEV 방식)이 생성형 세계모델보다 언제, 왜 유용한지를
> frozen JEV와 학습한 LLM으로, 여러 step rollout과 세 환경에서 검증한다.

| RQ | 질문 | 주요 비교 | 답이 들어가는 곳 |
|---|---|---|---|
| RQ1 방식 | 선택지로 묻기(타입화)가 다음 상태 쓰기(생성형)보다 나은가? 차이는 형식 오류·확률·내용 중 어디서 오는가? | 타입화 vs 생성형, 생성형 변형 (샘플링, 형식 제약) | 표 1, 그림 3, 표 3 |
| RQ2 출처 | frozen JEV와 학습 LLM은 정확도·데이터 효율·일반화·비용에서 어떻게 다른가? | JEV vs 학습 곡선, ID vs OOD | 그림 4, 표 4 |
| RQ3 horizon | rollout이 길어질 때 예측 → 결정 → 성공의 연결은 어디서 끊기는가? | k = 1..8, H = 1/2/4, 고정 plan bank | 그림 3, 그림 5 |
| RQ4 환경 | 결론이 세 환경에서 유지되는가? 환경의 예지력 요구와 어떻게 관련되는가? | TextWorld / ALFWorld / ScienceWorld | 그림 2, 표 1 |

## 1. 설계

### 1.1 요인

| 요인 | 수준 | 비고 |
|---|---|---|
| 질의 방식 | 타입화 / 생성형 | KIIS와 같은 정의 (`../kiis2026f/실험계획.md` §1.2–1.3) |
| 생성형 변형 | 1회 greedy (기본) / n=4 샘플링으로 확률 추정 / 형식 제약 디코딩 | 타입화의 이점을 형식·확률·내용으로 나누기 위한 것 (RQ1) |
| 세계모델 출처 | JEV frozen / 오픈 LLM zero-shot / 오픈 LLM 학습 (예산 5단계) / JEV 증류 (허가 시만) | |
| 모델 크기 | Qwen3-4B (KIIS와 같음) / Qwen3-8B | 선택: 다른 계열 1개 |
| rollout 길이 | 예측 k = 1..8, 계획 H = 1 / 2 / 4 | |
| 계획기 | 기본 (KIIS 효용식) / 개선 변형 (F7, 선택) | |
| 환경 | TextWorld (구조 3종) / ALFWorld / ScienceWorld | F1 게이트를 통과한 환경만 |

### 1.2 arm

| arm | 방식 | 세계모델 | 용도 |
|---|---|---|---|
| `C` | — | 없음 | 기본 에이전트 |
| `validity`, `oracle` | — | 엔진 | 기준선 (유효성만 / 완전한 예측) |
| `persistence` | — | "아무것도 안 바뀐다" | 예측 평가의 바닥선 |
| `A_jev` | 타입화 | JEV, 재귀 1-step | 주 JEV arm |
| `A_dir`, `A_end`, `A_val` | 타입화 | JEV, direct-horizon 방식 | 질의 분해 ablation (이전 `A`, `Aend`, `Aval`) |
| `B0_typed`, `B_typed@N` | 타입화 | Qwen, 학습 없음 / 전이 N개 학습 | |
| `D0_gen`, `D_gen@N` | 생성형 | Qwen, 학습 없음 / 전이 N개 학습 | |
| `D*_gen_s4`, `D*_gen_cd` | 생성형 | 위와 같음, 4회 샘플링 / 형식 제약 | RQ1 분해 |
| `B_kd` | 타입화 | Qwen, JEV 확률로 증류 | **TypeSafe 서면 허가가 있을 때만** |
| `…@8B` | | Qwen3-8B 버전 | 모델 크기 |

모든 arm은 환경마다 같은 정책·후보·계획기·효용함수를 쓴다.

### 1.3 여러 step을 다루는 방식

- 세계모델은 한 걸음 전이 모델이고, 계획기가 예측한 상태를 다시 넣어 여러 step을 상상한다
  (KIIS와 같다).
- **예측 평가**: k = 1..8 step rollout의 상태 완전일치를 모델별로 그린다.
- **계획 평가**: H = 1 / 2 / 4. H를 비교할 때는 정책이 H=4 계획을 **한 번만** 만들게 하고 prefix
  길이만 제한한다 (`설계.md` §23). H마다 정책을 다시 돌리면 후보 차이가 섞인다.
- **고정 plan bank**: 상태 수백 개에서 후보를 한 번 만들어 고정하고, 모든 세계모델이 같은 후보를
  채점한다. decision regret(엔진이 고른 것 대비 손실), action-shuffle 대조, 예측 오류 악용률
  (상상 속에서는 성공, 실제로는 실패인 선택의 비율)을 여기서 잰다.
- 이전 관찰: H=4에서 예측은 유지되는데(beam 포함 99.5%) 성공률은 31%로 떨어졌다 (C3 조건,
  `artifacts/R_h4_fix`). 원인이 계획기인지 예측 오류 악용인지를 plan bank로 가른다.

## 2. 환경

### 2.1 TextWorld

| 구조 | 내용 | 역할 |
|---|---|---|
| T1 함정 world | KIIS와 같음: 방 2, 상자·열쇠·잠긴 문, 목표물·미끼 음식 | ID, KIIS 결과와 연결 |
| T2 | 방 3, 문 2, 열쇠 2 (각 문에 맞는 열쇠 하나) | 구조 OOD, 긴 의존 체인 |
| T3 | 중첩 용기, 맞지 않는 열쇠 포함, 받침대 여러 개 | 구조 OOD, precondition이 복잡함 |

- 어휘는 KIIS와 같은 train/val/test 분할을 쓴다.
- **난도 축**: 구조마다 "유효하지만 목표를 전진시키지 않는 행동의 비율"을 엔진으로 정확히 계산해
  headroom 분해(그림 2)의 x축으로 쓴다.

### 2.2 ALFWorld

| 항목 | 계획 |
|---|---|
| 관측 | **완전관측 변형**: PDDL 사실로 상태를 만든다 (TextWorld와 같은 조건). 표준 부분관측 결과와 직접 비교하지 않고, 논문에 명시한다 |
| 과제 | 6종 (pick_and_place, look_at_obj, clean, heat, cool, pick_two) |
| 분할 | train (학습 전이) / valid_seen (ID test) / **valid_unseen (처음 보는 장면, OOD)** |
| 정책의 행동 후보 | 표준대로 **가능한 명령 목록을 준다**. 그래서 유효성은 이미 주어지고 **목표 지향 예측만** 남는다 — TextWorld(정적 catalog만 줌)와 대조되는 설정 |
| 상태 스키마 | 에이전트 위치, 물체의 직접 parent (용기·받침대·인벤토리), 용기 개폐, 물체 속성 (씻음·데움·식힘·자름·켜짐) |
| 질문 선택 | 목표 물체 + 행동이 언급한 물체 + 에이전트 위치. 미래를 보지 않는 결정적 규칙으로만 고른다 (`설계.md` §10.2) |
| 선택지 수 | 위치 선택지가 수십 개. JEV Choice 한도(255개) 안 |
| 분기 | `env.copy()`가 되는지 먼저 확인. 안 되면 replay (예비 probe에서 분기 1회 약 5초 — 느리다) |
| oracle | PDDL 계획기 거리 (`policy_commands`) |
| 예비 결과 | `artifacts/alf_probe8.log`: 상태 24개의 유효 행동 794개 중 목표를 전진시키는 것 4.8%, 비가역 0% — 유효성만으로는 풀리지 않는 환경 |

### 2.3 ScienceWorld

**타당성 probe를 먼저 하고, 게이트를 통과할 때만 본 실험에 넣는다.** probe에서 확인할 것:

| 확인할 것 | 없으면 |
|---|---|
| 전체 상태(물체, 위치, 속성)를 구조화해서 얻는 방법 | 관측 텍스트 파싱이 필요 → 공수가 커서 제외 검토 |
| 상태 분기 (저장·복원) | replay 비용을 재고 판단 |
| 유효 행동 목록 | ALFWorld처럼 후보로 쓴다 |
| 정답 궤적 | oracle·headroom 계산에 필요 |
| 상태 변수가 작은 과제 부분집합 | 예: 물질 상태 변화 계열. 과제 수를 줄여서라도 넣는다 |

### 2.4 환경 게이트 (F1 끝)

환경마다 둘 다 만족해야 본 실험에 넣는다.

1. **기술**: 상태 직렬화, 정답 라벨, 분기, 설정 해시가 동작한다. dev에서 C·oracle이 끝까지 돈다.
2. **예지력 요구**: dev headroom 분해에서 oracle − C ≥ 10%p, oracle − validity ≥ 5%p.
   ALFWorld처럼 유효성이 주어진 환경은 oracle − C만 본다.

통과하지 못한 환경은 논문의 "환경이 예지력을 요구하는가" 절(그림 2)에만 넣고 본 실험에서 뺀다.

## 5. 단계

### F0 — 인수와 결정 (1주)

- [ ] KIIS 코드·결과 인수. KIIS 설정 해시 목록을 이 폴더에 기록
- [ ] 투고처 결정 → [투고대상.md](투고대상.md) §4 채움
- [ ] TypeSafe에 공개 범위 서면 확인 요청 (결과 공표, 원시 응답 보관, B_kd 학습)
- [ ] JEV 버전·가격 확인
- [ ] GPU 확보 (연장 또는 추가 자원) — §8 추정치 기준

**통과**: 투고처와 마감이 정해졌고, JEV 공개 범위 요청을 보냈다.

### F1 — 환경 이식과 타당성 (3–4주)

- [ ] TextWorld T2·T3 생성기, 난도 축 계산
- [ ] ALFWorld 완전관측 어댑터: 상태 직렬화, 스키마, 목표 원자, 분기, oracle
- [ ] ScienceWorld 타당성 probe (§2.3 표)
- [ ] 환경마다 dev에서 C / validity / oracle headroom 분해
- [ ] 환경마다 정책 결정 (dev), §3 표 채움

**통과**: §2.4 게이트. 결과를 환경별로 기록하고 본 실험에 넣을 환경을 확정한다.

### F2 — 세계모델 일반화 (2주)

- [ ] 스키마에서 타입화 질문과 생성형 출력 형식을 자동으로 만드는 코드 (환경 공통)
- [ ] 타입화 backend (JEV, Qwen), 생성형 backend (greedy / n=4 샘플 / 형식 제약) — 모두 같은 rollout 코드
- [ ] direct-horizon arm (`A_dir`, `A_end`, `A_val`)을 새 조건에서 복원
- [ ] 계약·파서 왕복·parity·누출 테스트를 환경마다

**통과**: 환경마다 모든 arm이 dev 1 episode씩 완주, 테스트 전부 통과.

### F3 — 데이터와 학습 (3주)

- [ ] 환경마다 전이 생성 (KIIS K2 방식, 상태·행동 분포를 환경에 맞게)
- [ ] 학습 곡선: 전이 250 / 1k / 4k / 16k / 64k × {타입화, 생성형} × 환경
- [ ] 최대 예산은 학습 seed 3개
- [ ] 모델 크기: Qwen3-8B로 최대 예산 1회씩
- [ ] (허가 시) `B_kd`

**통과**: val loss가 줄고, 예산이 늘수록 val 정확도가 오른다 (단조가 아니면 원인 기록).

### F4 — 예측 평가 (2주)

- [ ] k = 1..8 rollout, 모든 세계모델, ID와 OOD
- [ ] 보정: 타입화는 NLL·Brier·ECE, 생성형은 n=4 샘플로 같은 지표
- [ ] JEV 비결정성: 반복 호출로 σ와 argmax 뒤집힘 비율
- [ ] 동봉 오염 대규모: 실행 여부 질문을 단독 / state에 행동열만 / endpoint 질문 k개와 동봉 / 무관 질문과 동봉 × 반복 3 (이전 n=10 결과의 확증)
- [ ] 세계모델 세 조건 (`아이디어.md` §4)을 방식별로: 순서 민감 쌍 여러 종류, 목표 재사용 5개

**통과**: 모든 모델이 같은 rollout 집합에 대해 결과를 갖는다.

### F5 — 고정 plan bank (2주)

- [ ] 환경마다 상태 300–500개 (여러 arm의 궤적에서 추출) × K=8, H=4 계획을 한 번 생성해 고정
- [ ] 모든 prefix를 엔진으로 라벨 (끝 상태, 무효 수, 실제 효용)
- [ ] 모든 세계모델로 채점: decision regret, 엔진과 첫 행동 일치율, 효용 순위 상관
- [ ] H = 1 / 2 / 4 제한, action-shuffle 대조, 예측 오류 악용률

**통과**: 같은 bank에 대해 모든 세계모델 결과가 있다.

### F6 — closed-loop 본 실행 (3주)

- [ ] 환경 × arm × seed 3개. episode 수는 F1 파일럿의 불일치율로 정한다 (짝차이 CI 반폭 ±6%p 목표)
- [ ] 필수 arm: C, validity, oracle, A_jev, B0_typed, B_typed@최대, D0_gen, D_gen@최대. 나머지 arm은 plan bank 결과를 보고 선택

**통과**: 예정 episode 전부 결과나 실패 사유가 있고, 설정 해시가 같다.

### F7 — 계획기 개선 (선택, 2주)

F5에서 H=4 붕괴의 원인이 "예측 오류 악용"으로 나왔을 때만 한다.

- [ ] 후보 변형: 불확실성 벌점, 깊이 할인, beam 최솟값 효용
- [ ] **dev에서 하나를 고르고, test에서는 한 번만 돈다.** 고른 과정을 §12에 적는다

### F8 — 분석과 집필 (3–4주)

- [ ] 스크립트 하나가 raw 로그에서 모든 표·그림과 `results/slots.json`을 만든다
- [ ] §6 해석 규칙대로 문장 선택

## 6. 사전 기대 (각 단계 시작 전에 커밋)

| # | RQ | 기대 | 판정 |
|---|---|---|---|
| E1 | RQ1 | 학습 없이는 모든 환경에서 타입화 > 생성형 (B0 > D0) | 성공률 짝차이, k-step 정확도 |
| E2 | RQ1 | 생성형 샘플링·형식 제약이 그 차이의 일부를 줄인다 — 차이가 형식·확률·내용으로 나뉜다 | D0, D0_s4, D0_cd, B0 비교 |
| E3 | RQ1 | 학습하면 방식 차이가 줄어든다 | 예산별 (B − D) |
| E4 | RQ2 | 학습 타입화 LLM이 JEV를 넘는 예산 N*가 있고, 환경이 복잡할수록 N*가 크다 | 학습 곡선 |
| E5 | RQ2 | 처음 보는 구조·장면에서 학습 모델의 하락폭이 JEV보다 크다 | ID vs OOD |
| E6 | RQ3 | k가 늘면 예측은 완만히 떨어지지만, H=4의 decision regret은 예측 오류로 설명되는 것보다 크게 는다 | plan bank |
| E7 | RQ4 | 세계모델의 이득(validity 대비)은 환경의 예지력 요구(oracle − validity)와 함께 커진다 | 환경·구조별 산점 |

**해석 규칙**은 KIIS와 같다. CI가 0을 포함하면 "구분되지 않는다"라고 쓰고, "비슷하다"는 사전에
정한 margin(±5%p)의 동등성 검정(TOST)을 통과할 때만 쓴다. 기대와 반대로 나와도 표와 그림은
그대로 싣는다.

## 7. 지표와 통계

| 층위 | 지표 |
|---|---|
| closed-loop | 성공률, steps, 무효율, 생성형 파싱 실패율, 세계모델 비용 (JEV 요청·$, GPU-초), 학습 GPU-h |
| 예측 | k-step 상태 완전일치 (주 지표), 변수 정확도, 바뀐 변수 정확도, 실행 여부 정확도, NLL·Brier·ECE |
| 결정 | decision regret, 엔진과 첫 행동 일치율, 효용 순위 상관, 예측 오류 악용률 |
| 세계모델 조건 | 순서 민감 쌍 정확도, 목표 재사용 시 추가 호출 수와 정확도, conjunction bound 위반률 |

- 독립 단위(world / 장면 / variation)로 클러스터 paired bootstrap 95% CI.
- 환경 여러 개에 걸친 같은 비교는 Holm으로 보정한다.
- 질문 수나 prefix 수를 독립 표본으로 세지 않는다.
