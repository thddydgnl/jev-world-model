## 1. RQ 별 논증

### RQ1. typed 판단 모델이 행동 결과 예측 모듈로 작동하는가

**답: 작동한다. 단, 질의 분해가 성패를 가른다.**

이것이 본 연구의 가장 새로운 발견이다. 같은 모델·과제·planner에서
분해 방식만 바꿨을 때:

| 분해 | 에이전트 성공률 |
|---|---:|
| endpoint 를 통째로 질의 (`설계.md` 원안) | **0.0%** |
| 유효성만 질의 | 83.3% |
| 유효성 + endpoint 분리 | **97.9%** |
| 재귀 1-step + 전체 상태 | 95.8% (요청 38%) |

근거:
- 사전 등록된 순서 교환 검사(`설계.md` §9): **0/18**, 18/18 동일 실패 양상
- 기작: 명령이 항상 성공한다고 가정 → planner가 실행 불가 계획 선택 → no-op
  → 상태 불변 → 무한 루프 (무효율 96.2%)
- 유효성을 **직접** 물으면 91.6% / 92.2%
- 정상 실행 시 endpoint 예측 **100%** (845건)
- ablation: 유효성 질문 제거 = **0.0%** → 분해의 기여 **+97.9%p**

**부가 발견 — 같은 요청에 무엇을 넣느냐도 답을 바꾼다.** 동일 유효성 질문을
단독으로 물으면 p=0.285(정답 방향), 상태질문 6개와 동봉하면 0.576(오답).
차이 +0.291, SE 0.028. 이 변경 하나가 순서 민감도를 22.2% → 77.8%로 바꿨다.

**`아이디어.md` §4 세 조건 충족 여부:**

| 조건 | direct-horizon | 재귀 |
|---|---|---|
| 1. 미래 사실 출력 | ✅ | ✅ |
| 2. 행동·순서 민감 | ❌ 0/18 | ✅ **14/18** |
| 3. 목표 독립·재사용 | ❌ | ✅ **추가 호출 0, 18/18** |

### RQ2. frozen JEV vs 환경 적응 LLM — 정확도·비용·일반화

**현재: 미측정.** arm B가 필요하다.

우리 발견이 RQ2를 날카롭게 만든다. **JEV가 질의 분해를 필요로 한 이유는
전이 동역학을 학습한 적이 없어서다.** 환경 정답으로 학습한 B는 precondition을
직접 배우므로 분해가 필요 없어야 한다.

**사전 등록할 예측:**

> **P-B1.** naive 분해(endpoint 통째 질의)에서 A는 0.0%, **B는 작동한다.**
> 분해의 필요성은 모델이 동역학을 모르기 때문이지 인터페이스의 한계가 아니다.
>
> **P-B2.** 같은 분해를 줬을 때 B ≥ A. 특히 **무효 명령이 포함된 prefix**에서
> 격차가 크다 (A의 측정된 약점).
>
> **P-B3.** A는 학습 비용 0·추론 과금, B는 학습 비용·추론 무료.
> label 예산이 작으면 A가, 크면 B가 유리한 교차점이 존재한다.

P-B1이 맞으면 RQ1의 발견이 **"인터페이스 설계는 모델이 무엇을 모르는지에
따라 필요해진다"**로 일반화된다. 이게 RQ1과 RQ2를 하나로 묶는 고리다.

### RQ3. 어떤 예측 품질이 행동 개선을 만들고, horizon은 어디서 끊기는가

**답 (a): 개선 여지의 대부분은 "행동 유효성"이다.**

| 환경 | oracle − validity | 유효성이 설명하는 비율 |
|---|---:|---:|
| 쉬운 world | **+2.1%p** | **97%** |
| 어려운 world | +18.8%p | 77% |

→ **방법론적 선행 조건**: WM이 기여할 여지가 없는 환경에서는 어떤 WM도
평가할 수 없다. 대부분의 WM 연구가 이 검사를 하지 않는다.

**답 (b): horizon 병목은 예측기가 아니라 planner다.**

| depth | 상태 완전일치 | beam 포함 |
|---:|---:|---:|
| 1 | 95.7% | 100.0% |
| 2 | 71.7% | 100.0% |
| 3 | 69.0% | 99.8% |
| 4 | 67.9% | **99.5%** |

예측은 depth 1→2에서 한 번 떨어진 뒤 **평평하다**(지수 붕괴 아님).
그런데 에이전트 성공률은 h=2 95.8% → h=4 31.2%, 무효율은 h=4가 오히려
가장 낮다(18.5%).

→ `설계.md` §22.3이 요구한 "예측과 행동의 분리 측정"의 결과다.

## 3. 두 개의 정리해야 할 문제

### 3.1 수치가 4개 조건에 걸쳐 있다

결함을 하나씩 고치면서 조건이 바뀌었는데 매번 전량 재측정하지 않았다.

| 조건 | 추가된 것 | 측정된 것 |
|---|---|---|
| C1 | 정책 행동 이력 | arm A **93.8%** |
| C2 | + planner 실패 기억 | A **97.9%**, R h=2 **95.8%**, R h=4 **39.6%** |
| C3 | + 무효 패널티 `/h` 제거 | R h=2 **93.8%**, R h=4 **31.2%** |
| **C4** | + **유효성 질문 분리** | **intrinsic 만** |

**가장 좋은 예측기(C4)로 closed-loop 에이전트를 한 번도 돌리지 않았다.**
→ 논문 표는 C4로 전 arm 재실행해 만든다.

### 3.2 CI 가 없다

전부 단일 seed. 실측 노이즈 **±7%p**. `A 97.9% vs R 95.8%`(2.1%p)는
현재 읽을 수 없다. `설계.md` §22.2대로 다중 seed + world-clustered bootstrap
필수.

## 8. 우리 발견을 원안 어디에 넣는가

원안(RQ1–RQ3, arm A/B/C, Contribution 1–3)은 유지한다. 발견은 아래에 배치한다.

### 8.1 구조 일치 여부 — 먼저 정리

**arm A는 계획된 A4(direct-horizon)가 맞다.** 다만 질의 분해가 6군데 다르고,
그 차이가 0.0%와 97.9%를 가른다.

| 항목 | 계획 | 구현 |
|---|---|---|
| 전체 구조 / 정보 경계 §3.5 / 선택지 완전성 §24 | — | **동일** |
| 질문 대상 §10.1 | 6종 | 목표 원자 3 + conjunction |
| invalid 질의 §10.1 | `{0..h}` Choice 하나 | **명령별 이진** |
| 조합 §13.1 | prefix endpoint 직접 | **실행 패턴 혼합** |
| 요청 단위 §7 | prefix당 1요청 | **endpoint / 유효성 분리** |
| `query_catalog` §7 | state에 포함 | 제거 (arm B 비교 시 복원) |
| 효용 §11 | `−λ·N/h` | **`−λ·N`** |
| 실패 기억 | 없음 | 추가 (§3.5 근거) |

**arm R은 원안이 부록으로 미뤄둔 후보 A2다** (`아이디어.md` §7, `설계.md` §13.3).
§13.3의 금지선("독립 marginal argmax + hardcoded dynamics")은 지켰다 —
`project_state`는 타입 배타성과 미커버 사실 이어받기만 적용하며, 전이 규칙을
넣지 않는다(160/160 전이로 검증).

### 8.2 배치

| 발견 | 들어갈 곳 | 원안 대비 |
|---|---|---|
| **F1** 질의 분해가 0%↔98%를 가른다 | **Contribution 1 의 핵심** · RQ1 · §5 | 원안은 "인터페이스가 존재한다"였다. **"설계가 성패를 정한다"로 승격** |
| **F2** 같은 요청에 무엇을 넣는지가 답을 바꾼다 (0.285 vs 0.576) | Contribution 1 하위 · **신규 AB10** | 원안에 없음 |
| **F3** 재귀 A2 가 세 조건 충족·요청 38%·목표 독립 | **arm A-rec 으로 A/B/C 에 추가** · RQ1 | 원안은 부록 보류. **본문 승격** |

### 8.5 원안 대비 아직 안 한 것 — 3건

1. **decision regret 미계산.** 원안의 핵심 그림이 *"행동 차이에 민감한 예측과
   decision regret의 관계"*인데 (`아이디어.md` §24), 한 번도 계산하지 않았다.
   로그는 저장 중이다(`설계.md` §22.3).
2. **AB6 의 action-shuffle 미실행.** F6("planner 가 병목")을 주장하려면 필수다.
   지금은 oracle 만 있다.
3. **horizon 실험 방식이 원안과 다르다.** §23은 H=4 plan bank 하나로 prefix
   길이만 제한하라고 한다. 우리는 H마다 정책에 다시 생성시켜 candidate 변화가
   섞였다. **h 곡선을 다시 만들 때 고쳐야 한다.**
