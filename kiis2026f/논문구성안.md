## 5. 절별 구성 (9/30 개정 원고)

원고의 글은 [`paper/원고.tmpl.md`](paper/원고.tmpl.md)가 기준이다. 여기에는 절마다 무엇을 말하는지만 적는다.

### 1. 서론

- **¶1 배경.** LLM 에이전트는 행동의 결과를 모른 채 행동해 무효하거나 무관한 행동을 반복한다. 월드 모델로 LLM을 그대로
  쓰거나 [1] 파인튜닝해 쓰는 방법 [2]이 제안되었다 (사용자 검토 2번). 이 방법들은 다음 상태를 글로 생성하며, 학습 없는
  LLM의 예측은 부정확하다고 보고되었다 [3]. [3]은 학습 없는 LLM만 평가했으므로 파인튜닝한 경우까지 넓혀 쓰지 않는다.
- **¶2 제안과 비교.** 결정 모델 JEV [4]는 상태와 질문을 받아 미리 정한 선택지 위의 확률을 반환한다. 이를 월드 모델로 쓰는
  방법을 제시하고(선택지로 묻고 답으로 다음 상태를 구성), LLM을 그대로 쓴 경우·파인튜닝한 경우와 비교한다. LLM에도 선택지로
  물어(결정형) 생성형과 비교한다.

### 2. 방법 (그림 1)

- **2.1 월드 모델을 쓰는 에이전트.** 완전관측 TextWorld [5], 정책 Qwen3-4B [6]가 길이 2의 후보를 내고 계획기가 월드 모델의
  예측으로 고른다. 효용은 한 문장으로 (목표에 가깝고 실행되지 않을 명령이 적은 후보). 실패 기억. 정책·계획기는 공통.
- **2.2 결정 모델을 월드 모델로.** 한 걸음 예측의 반복, 전이 규칙 없음. 결정형: 행동 하나에 질문 7개 (실행 여부 1 + 상태 변수
  6), 선택지 확률에서 가장 높은 값으로 다음 상태, 실행 확률로 폭 4 beam. 생성형: 사실 목록을 쓰게 하고 파서로 읽음. **파싱할
  수 없는 응답은 한 번 다시 생성하고 그래도 실패하면 "실행 안 됨"** — 결과 해석이 이 규칙에 기댄다.
- **2.3 비교하는 월드 모델.** A = JEV (jev-1.13.0, 과제 학습 없음). LLM(Qwen3-4B): 학습 없이 결정형 B0·생성형 D0, LoRA [7]
  파인튜닝 결정형 B·생성형 D (학습용 world 150개의 같은 전이 {R14}개). 기준선 C, C_fm. 참조선 oracle (성능 상한 아님).

### 3. 실험 (표 1, 그림 2)

- **3.1 설정.** 과제와 목표, 최단 풀이 6개 행동, 평가 world 24개(새 이름), episode 수, 성공·무효율의 정의, world 단위 CI.
  과제와 정책 설정은 예비 실험을 거쳐 평가와 분리된 world에서 월드 모델 없는 기준선의 성공률로 정했다 (R17: 월드 모델은
  oracle을 넘지 않는지 확인하는 데만 돌렸다). v1·v2의 이력은 본문에 쓰지 않는다 (사용자 검토 4번).
- **3.2 결과.**
  - **월드 모델의 효과** (H1·H1b): C → C_fm → A, B·D. 실패 기억만으로 설명되지 않는 이득 (R1, R15).
  - **학습 없이 쓸 때** (H2, H5): JEV는 oracle과 구분되지 않음. LLM은 결정형 B0 > 생성형 D0이고 D0 < C_fm. 원인은 형식
    (R12, R19, 그림 1). 파싱된 응답만 보면 D0가 낮지 않음 → 결정형의 이점은 형식 견고성. 예측 정확도는 JEV가 훨씬 높고
    학습 없는 LLM은 persistence보다 낮음 (R11). 성공률의 A − B0는 구분되지 않음 (R8).
  - **파인튜닝했을 때** (H3, H4 k-step, H7): B·D는 oracle과 같은 결과이고 k-step도 JEV보다 정확, 파싱 실패가 사라져
    **성공률에서** 두 방식의 차이도 사라짐 (k-step에는 B − D +1.0%p [0.1, 2.0]가 남아 "성공률에서"로 한정한다). **그러나 평가 world는 구조가 학습과 같다 (R20)**. 새 구조에서는 B·D가 JEV보다 낮고 하락폭이
    JEV보다 큼 (R16). "파인튜닝의 이득은 학습한 구조 안에 머물렀다."

### 4. 결론

- 세 결과를 두 문장으로. 한계는 한 문장 (한 가지 과제 구조와 LLM, 한 가지 파싱 실패 처리 규칙)으로 줄이고 향후 연구와
  묶는다 (사용자 검토 6번). 파싱 실패 처리 규칙은 H2의 크기가 기대는 설계 선택이라 범위에 남긴다 (실험계획 §11, 9/30).

## 9. 쓰지 않을 주장

- 결정형이 생성형 월드 모델 **전반**보다 낫다 — 이 조건(Qwen3-4B 한 모델, 이 데이터, 이 파서)에서만 말한다
- **결정형이 더 정확한 월드 모델이다** — 한 step 예측 내용은 같았고, 파싱된 응답만 보면 생성형이 낮지 않았다 (R12).
  이점은 "형식 견고성"으로만 쓰고, 그 크기가 파싱 실패 처리 규칙에 달려 있다는 것을 밝힌다
- 학습한 LLM과 JEV 중 closed-loop에서 어느 쪽이 낫다 — H4는 구분되지 않는다 (셋 다 oracle과 같은 수준). "동등하다"도 쓰지 않는다
- JEV가 학습 없는 LLM보다 closed-loop에서 낫다 — H5는 closed-loop에서 구분되지 않는다. k-step에서만 말한다
- 결정형이 오류 누적을 줄인다 — H8은 구분되지 않았다
- 파인튜닝하면 결정형과 생성형의 차이가 없다 — 성공률에서만 그렇다 (B − D 0). k-step 정확도는 B가 1.0%p [0.1, 2.0] 높다
- 파인튜닝한 LLM의 예측이 부정확하다고 알려져 있다 — [3]은 학습 없는 LLM만 평가했다
- 월드 모델이 oracle보다 낫다 — oracle을 넘는 에이전트는 없었다 (JEV +0.7%p는 구분되지 않음)
- 학습한 B·D가 완벽한 예측기다 — 성공 여부가 oracle과 같았을 뿐, closed-loop 후보 예측의 0.3–1.1%는 틀렸다
  (상태 완전일치 한 step B 99.7% · D 99.3%, 두 step 98.9% · 99.1%)
- 다른 환경이나 실세계로 일반화된다 — TextWorld 한 구조뿐이다
- JEV의 내부 표현이나 학습 목적(RLCD)이 원인이다 — 식별할 수 없다
- 두 에이전트가 "동등하다" — 신뢰구간이 0을 포함한다는 이유만으로는 쓸 수 없다
- 긴 horizon 계획에 관한 주장 — closed-loop은 H=2만 쟀다
- oracle을 "성능 상한"이라고 부르는 것 — 같은 후보·효용에 완벽한 예측을 넣은 진단 기준이다
- 비가역 행동이나 함정에 관한 주장 — 과제의 함정(목표 음식 먹기)은 한 번도 발동하지 않았다. D0 분석의 "음식 없이 먼 방에
  들어간 상태"를 "함정"이라고 부르지 않는다
- 학습한 LLM이 새 구조나 다른 과제에 일반화한다 — X1 rollout 범위에서만 말하고, 결과는 오히려 반대다 (H7).
  평가 world는 처음 보는 이름이지만 구조가 같다 (전이의 69.5%가 학습 전이와 같은 구조, R20) — 3.2 "파인튜닝했을 때"
  문단에서 B·D의 결과 바로 뒤에 쓴다 (사용자 검토 3번)
- 결정형의 이점이 "질문 형식" 자체에서 온다 — 확률·beam, 연구자가 정한 상태 변수 틀과 분리되지 않았다
  (H8의 beam 1 대조가 beam만은 분리한다)
- "자연어 월드 모델보다" — 우리 생성형은 사실 목록 형식이다. "생성형(사실 목록) 월드 모델보다"로 한정한다
- 설정을 평가 결과로 맞춘 것처럼 읽히게 두는 것 — 3.1에 "예비 실험을 거쳐, 평가와 분리된 world에서 월드 모델 없는
  기준선의 성공률로 정했다"고 한 문장을 쓴다. v1·v2의 이력은 본문에서 빼고 발표 백업과 [실험계획.md](실험계획.md)에 둔다
- "설정을 정하는 데 월드 모델을 쓰지 않았다" — 보정의 단조성 점검(월드 모델이 oracle을 넘지 않는지)에는 월드 모델을 돌렸다
- 이전 조건(C1–C4)이나 v1·v2의 수치를 표 1과 섞는 것
- "최초"
