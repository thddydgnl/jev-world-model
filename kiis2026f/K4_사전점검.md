## dev 병렬 예행 실행

실제 K4와 같은 프로세스 묶음을 dev t000/r0, seed 20260921에서 한 번씩 실행했다.
GPU0: `core`와 `D_gen`; GPU1: `B0_typed,D0_gen`과 `B_typed`.
동시 실행 중 관측된 GPU 사용량은 각각 약 20.3GB/24GB였다.

네 프로세스 모두 정상 종료해 8/8 episode 결과를 기록했다. 모든 매니페스트의 공통 조건 해시는
`0fe479090329`, dev t000 지문은 `a837582ee526e8af`로 같고, 8개 arm의 step 0 후보
계획 목록도 완전히 일치했다. 선택 어댑터의 가중치 지문도 위 K3 기록과 일치한다.

| 작업 | 기록한 episode | 종료 상태 | 매니페스트 |
|---|---:|---|---|
| core | 4/4 | C cap(30), validity·oracle·A_jev 성공 | [core](../artifacts/kiis_k4_preflight/core/run_manifest.json) |
| zero_shot | 2/2 | B0_typed·D0_gen 성공 | [zero_shot](../artifacts/kiis_k4_preflight/zero_shot/run_manifest.json) |

C의 cap은 제한 내 완료 상태이며 dev 성능 우열로 해석하지 않는다. core에서 JEV 요청

확인에만 사용한다.

## 본실험 실행 단위

정책 seed는 `20260921`, `777`, `1234`의 세 개다. 각 seed에서 아래 네 작업을
별도 결과 경로로 실행한다. 공통 인자는 `--trap --split test --worlds 24 --roots 4
--cap 30 --horizon 2 --policy-seed <seed>`다. arm별 어댑터를 다른 arm의 프로세스에
적용하지 않는다.

| 작업 | GPU | `--arms` | 추가 인자 | seed당 episode |
|---|---:|---|---|---:|
| core | 0 | `C,validity,oracle,A_jev` | JEV 요청 예산 `--budget 3` | 384 |
| zero_shot | 1 | `B0_typed,D0_gen` | 없음 | 192 |
| typed | 1 | `B_typed` | `--adapter artifacts/kiis_k3/B_typed` | 96 |
| generative | 0 | `D_gen` | `--adapter artifacts/kiis_k3/D_gen` | 96 |

총 **12개 작업, 2,304 episode**. 결과 경로는 `artifacts/kiis_k4/<seed>/<작업>`로
고정한다. 실행 뒤에는 모든 작업의 `run_manifest.json`에서 코드 revision·조건 해시·arm 해시,
24개 world 지문, 96개 root, 완료/실패 사유를 확인한다. 서버 `REVISION`은 K4 직전의
커밋으로 다시 동기화한다.

## 일정·연장 확인

- 9/24 dev 예행 실행의 작업별 소요 시간은 core 338초, zero_shot 316초,
  typed 188초, generative 315초였다. 작업마다 K4의 288개 root로 단순 외삽하면
  약 27·25·15·25시간이며, 병렬 완료까지 대략 25–30시간이다. test world의
  난이도와 외부 API 지연·재시도에 따라 더 걸릴 수 있다.
