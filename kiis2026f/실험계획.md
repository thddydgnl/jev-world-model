## 1. 에이전트 정의

모든 에이전트는 같은 정책(Qwen3-4B), 같은 후보 행동열, 같은 계획기·효용함수를 쓴다.
다른 것은 **후보를 평가하는 세계모델** 하나다.

| 논문 표기 | 코드 arm | 질문 방식 | 세계모델 | 환경 데이터 학습 |
|---|---|---|---|---|
| **C** 기본 에이전트 | `C` | — | 없음 — 정책 1순위 계획의 첫 행동 | — |
| **A** | `A_jev` | 타입화 | JEV `jev-1.13.0`, frozen | 없음 |
| **B0** | `B0_typed` | 타입화 | Qwen3-4B | 없음 |
| **B** | `B_typed` | 타입화 | Qwen3-4B + LoRA | 전이 N개 |
| **D0** | `D0_gen` | 생성형 | Qwen3-4B | 없음 |
| **D** | `D_gen` | 생성형 | Qwen3-4B + LoRA | 전이 N개 (B와 같은 데이터) |
| 참조 | `validity` | — | 엔진의 실행 가능 여부만 | — |
| 참조 | `oracle` | — | 엔진의 실제 결과 | — |

- validity oracle은 "무효 행동만 걸러내면 어디까지 가는가", full oracle은 "같은 후보·효용에서
  예측이 완벽하면 어디까지 가는가"를 보여 주는 기준선이다.
- 기호는 `아이디어.md`와 `설계.md`의 원안을 따른다 (A = JEV, B = 학습 LLM, C = 세계모델 없음,
  D = 생성형).

### 1.1 세계모델이 하는 일 — 한 걸음 예측을 반복해 여러 step을 상상한다

세계모델은 (상태, 행동) → 다음 상태를 예측하는 **전이 모델**이다. 계획기는 이 예측을 반복 적용해
(예측한 상태를 다시 입력) 후보 행동열을 H=2 step 끝까지 상상하고, 상상한 끝 상태에서 목표 충족을
계산한다. Dreamer, MuZero 같은 세계모델도 같은 구조다.

- 두 방식은 **한 걸음을 어떻게 묻느냐**만 다르다. 여러 step으로 굴리는 코드(재귀 rollout)와
  계획기는 하나다.
- 전이 규칙은 넣지 않는다. 예측한 값으로 상태를 다시 쓰는 것 외에 연구자가 동역학을 보정하지 않는다.
- closed-loop 계획은 H=2로 고정한다. 더 긴 상상은 그림 2에서 k = 1..4 예측 정확도로만 잰다.
  이전 실험에서 H=4 계획은 예측이 유지되는데도 성공률이 31%까지 떨어졌고, 원인이 계획기
  쪽이라 2쪽 안에서 다룰 수 없다 (fullpaper RQ3).

### 1.2 타입화 방식 — JEV 방식 (A, B0, B)

(상태, 행동)마다 두 가지를 묻는다. 답은 **연구자가 준 선택지 위의 확률**이다.

1. 실행 가능성 `executes / fails` — 별도 요청으로, 다른 질문과 섞지 않는다.
2. 상태 변수 6개 각각의 값 — 플레이어 위치, 휴대 물체 3개의 위치(먹어서 사라지면 `gone`),
   상자·문의 개폐. 선택지는 타입상 가능한 값을 전부 나열한다.

변수별 argmax로 다음 상태를 만들고, 실행 확률 p로 "실행됨(예측 상태)"과 "실패(상태 유지)"
두 가지를 가중해 beam 4로 굴린다 (현재 `src/wm/recursive_forecaster.py`).

- **A**: JEV API. 현재 `R` 구현 그대로다.
- **B0 / B**: Qwen3-4B가 JEV와 같은 payload를 텍스트로 받는다. 선택지를 A/B/C… 글자로 나열하고,
  다음 토큰 분포를 선택지 글자로 제한해 확률로 읽는다. JEV와 같은 응답 JSON을 돌려주는
  로컬 클라이언트(`LlmJudgeClient`)로 만들어 rollout 코드를 그대로 쓴다.

### 1.3 생성형 방식 (D0, D)

(상태, 행동)을 주고 **다음 상태를 직접 쓰게** 한다. 선택지는 주지 않는다.

```
result: executes        ← 또는 fails
in(k_0, I)              ← 결과 상태의 변하는 사실을 한 줄에 하나씩, 입력과 같은 표기
open(c_0)
at(P, r_0)
...
```

- **입력**: 타입화와 같은 `current_state` payload + 행동 + 출력 형식 설명.
  D0에는 dev world에서 뽑은 **형식 예시 1개**를 넣는다. K2에서 고정하고 이후 바꾸지 않는다.
- **디코딩**: greedy, 최대 320 토큰. 한 계획 step에 필요한 예측들은 배치로 생성한다.
- **확률 없음**: 예측이 하나뿐이라 beam 폭은 1이고, 실행 여부는 0 또는 1이다.
  이것도 두 방식의 차이에 포함된다 (확률을 주는 것이 타입화의 장점인지가 Q2의 일부).
- **파서**: result 줄 → 실행 여부, 사실 줄 → 상태 변수 6개. 한 변수에 값이 0개거나 2개 이상이면
  파싱 실패다. 실패하면 한 번 다시 생성하고(temperature 0.7, 고정 seed), 그래도 실패하면
  "실패(상태 유지)"로 처리한다. 정책의 schema repair 1회 규칙과 같다. **파싱 실패율은 따로 보고한다.**
- **D0 / D**: 같은 Qwen3-4B, LoRA만 끔/켬.

### 1.4 학습 (B, D)

B와 D는 **같은 환경 전이 N개**로 학습한다. 다른 것은 정답을 주는 형식뿐이다.

| | 입력 | 정답 |
|---|---|---|
| B | payload + 질문 1개 + 선택지 | 정답 선택지 글자 1토큰 (전이 하나당 질문 7개) |
| D | payload + 행동 + 형식 설명 | result 줄 + 다음 상태의 사실 목록 |

- 라벨은 엔진 정답만 쓴다. JEV 출력은 학습에도 checkpoint 선택에도 쓰지 않는다 (MCA 2.3(b)).
- LoRA bf16, r=16, α=32, dropout 0.05, lr 1e-4, 2 epoch, val 전이 정확도로 epoch 선택.
  B는 선택지 순서를 예제마다 섞는다.
- N은 K2에서 잰 처리량으로 정했다: **6,000** (학습 1회 24 GPU-h 이내 규칙, §11). B는 전이당 질문이 7개라
  D보다 약 3배 비싸다 (전이당 6,475 vs 1,937 토큰).
- 정책과 LLM 세계모델은 **같은 Qwen3-4B 가중치**를 쓰고 LoRA만 켜고 끈다. 프로세스 하나에
  GPU 메모리 약 9–10GB라 GPU당 2 프로세스가 들어간다.

### 1.5 이전 실험과 달라진 점

| 항목 | 이전 (`docs/`, `artifacts/`) | 이번 | 이유 |
|---|---|---|---|
| JEV arm | direct-horizon + 실행 패턴 분해 (`A`) | 재귀 1-step (`A_jev` = 기존 `R`) | 타입화·생성형, JEV·Qwen이 모두 같은 rollout을 쓰게 |
| 비교 대상 | JEV vs 정책 | 2×2 (방식 × 학습) + JEV | JEV 방식 자체의 효용을 재기 위해 |
| B readout | `설계.md` §14 별도 head | 선택지 글자 확률 | 같은 출력 계약, B0를 같은 코드로 얻음 |
| 정책 seed key | (world, root, **arm**, step) | (world, root, step) | docstring 의도대로 모든 arm이 같은 randomness를 받게 |
| 무효 패널티 | `−λ·N/h` (`설계.md` §11) | `−λ·N` | 이전 C3에서 이미 변경 |
| 실패 기억 | 없음 (C1) | 있음 | 이전 C2에서 이미 추가 |
| world | 이름 4세트 × 접미사 3 = 12개 | dev / train / val / test 분할 | 누출과 과대 일반화 방지 |

그래서 **이전 closed-loop 수치는 표 1에 넣지 않는다.** 방법 절 동기로 예비 결과 하나
(순서 교환 검사 0/18 → 14/18, 슬롯 R13)만 인용한다.

## 3. world와 데이터 분할

이름(어휘)으로 나눈다. 기존 12개 world는 이름 4세트의 변형이고 개발 중에 계속 봤으므로
dev로만 쓴다.

| 분할 | 이름 | 규모 | 용도 |
|---|---|---|---|
| dev | 기존 4세트 (t000–t011) | 12 world × 4 root | K1 파일럿, 디버깅, D0 형식 예시 |
| train | train 어휘 | 150 world | B·D 학습 전이 |
| val | val 어휘 | 20 world | checkpoint 선택 |
| **test** | test 어휘 (처음 보는 이름) | 24 world × 4 root | 표 1, 그림 2 |

- 슬롯(용기·열쇠·받침대·문·음식·방)마다 어휘 목록을 만들고, dev 단어를 뺀 뒤
  train 60% / val 10% / test 30%로 나눈다. **test 이름은 학습에 한 번도 나오지 않는다.**
- test world는 K0에서 생성해 해시를 `run_manifest`에 기록하고, K4 전에는 결과를 보지 않는다.
- 새 구조(OOD)는 여유 과제다 (§9 X1).

| H1 성립 | 세계모델은 기본 에이전트의 성공률을 R1에서 R2–R6 수준으로 높였다 |
| H1 일부만 성립 | 어떤 세계모델이 도움이 됐고 어떤 것이 안 됐는지 그대로 쓰고, 무효율·파싱 실패율로 원인을 짚는다 |
| H2 성립 | 같은 LLM에서 질문을 선택지로 바꾸기만 해도 성공률이 R4에서 R3으로 올랐다 |
| H2 불성립 | 학습 없는 LLM에서는 생성형이 타입화보다 낮지 않았다 — JEV 방식의 이득은 JEV 모델에 있다 (H5와 함께) |
| H3 성립 | 학습하면 두 방식의 차이가 줄었다 — 타입화의 이점은 학습 데이터가 없을 때 크다 |
| H3 불성립 | 학습 후에도 타입화가 앞섰다 (또는 생성형이 앞섰다) — 방식 차이가 데이터로 사라지지 않는다 |
| H4 성립 | 전이 N개로 학습한 LLM은 JEV 방식을 frozen JEV 이상으로 재현했다 |
| H4 불성립 | frozen JEV가 전이 N개로 학습한 LLM보다 높았다 |
| H5 성립 | 같은 질문 방식에서 JEV는 학습 없는 LLM보다 높았다 |
| H6 | k-step 곡선을 그대로 기술한다 (어느 모델이 얼마나 떨어지는지) |

## 6. 지표와 통계

### 6.1 closed-loop (표 1)

| 지표 | 정의 |
|---|---|
| 성공률 | 30 step 안에 목표 원자 3개를 모두 만족한 episode 비율 |
| steps | 실패 episode 포함 평균 step (최대 30) |
| 무효율 | 실행되지 않은 행동 수 / 전체 step |
| 파싱 실패율 | 생성형만: 재생성 후에도 파싱에 실패한 예측 / 전체 예측 |
| 세계모델 비용 | A: episode당 요청 수·입력 토큰·$ / B0·B·D0·D: episode당 세계모델 GPU-초. 학습 GPU-h는 따로 |

- 독립 단위는 **world**다. arm끼리는 같은 (seed, world, root)로 짝짓는다.
- world-clustered bootstrap (B=4000)으로 성공률과 짝차이의 95% CI를 낸다. 한쪽만 성공한 episode 수도 보고한다.
- 표본 근거: 이전 C1 3-seed에서 A와 validity가 어긋난 비율이 18%였다. 이 비율이면 짝당
  288 episode에서 CI 반폭은 약 ±6%p다.

### 6.2 k-step rollout (그림 2)

| 지표 | 정의 |
|---|---|
| **상태 완전일치 (주 지표)** | k step 뒤 모델이 예측한 상태(타입화는 beam 1위, 생성형은 유일한 예측)가 실제 상태와 변수 6개 전부 같은 비율 |
| 변수 정확도 | 변수 6개 중 맞은 비율의 평균 |
| 실행 여부 정확도 | 각 step의 executes/fails 판단 정확도 (불균형 보정) |

- k = 1..4, 모델별 곡선. persistence를 바닥선으로 함께 그린다.
- 생성형의 파싱 실패는 틀린 것으로 센다.
- CI는 world 단위 bootstrap.
